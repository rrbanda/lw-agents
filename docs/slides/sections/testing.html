Test Generation

Automated Test Scaffolding

The test generation agent writes JUnit 5 tests to verify that the remediation fix works, then iteratively refines them until they pass. It follows the same SequentialAgent + LoopAgent pattern as remediation, with a dedicated evaluator–checker–fixer loop inside.

Phase 1: Test Writing

✍ initial_test_writer

Loads the junit-test-generation and scm-conventions skills via SkillToolset. Clones the repository, then uses OpenCode (via execute_bash) to generate JUnit 5 test files. Runs an initial mvn test to check if the tests pass.

SkillToolset execute_bash (build_bash_tool) clone_repository

Phase 2: Refinement Loop

🔄 test_refinement_loop · LoopAgent (max_iterations=3)

Three sub-agents cycle inside the loop. The evaluator runs tests, the checker decides whether to stop, and the fixer addresses failures:

test_evaluator
LlmAgent · runs mvn test
Grades PASS or FAIL
→
test_escalation_checker
BaseAgent (no LLM)
If PASS → escalate
→
test_fixer
LlmAgent
Fixes failing tests

test_evaluator

LlmAgent that runs mvn -B -q test via bash and responds with exactly GRADE: pass or GRADE: fail plus a summary of what needs fixing.

test_escalation_checker

TestEscalationChecker — a BaseAgent (no LLM). Reads test_evaluation from session state. If it contains grade: pass, it sets escalate=True to break out of the loop.

test_fixer

A separate LlmAgent instance (not the same as initial_test_writer — ADK requires unique parent bindings). Loads the same skills and tools to analyze failures and rewrite tests.

Phase 3: Tests PR

📦 test_pr_opener

Opens a separate pull request with only the test files. Branch naming: ai-tests/generated-<timestamp>. Test PRs are kept separate from remediation PRs so reviewers can evaluate the fix and its tests independently.

create_pull_request
Why separate PRs? Test generation is the validation layer. The remediation agent changes the dependency version; the test generation agent proves the change doesn’t break anything. Separate PRs mean reviewers can evaluate the fix and its tests independently — and either can be revised without blocking the other.
