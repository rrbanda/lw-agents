System Context

Where the Agent Service Fits

The ADK agent service is one component in a Tekton CI/CD pipeline. It receives work from a thin HTTP caller task and interacts with external systems for vulnerability data, version verification, and source control.

Four Integration Points

Tekton CI/CD Pipeline

Pipeline orchestrates the full build. call-ssc-agent is a thin Tekton Task that POSTs to the agent's HTTP API. Agent returns structured results (SELECTED, CVE_ID, PR_URL) mapped to Tekton result fields.

EvalHub on RHOAI 3.5

Two eval gates run before the agent: model-level safety (truthfulqa, toxigen, ethics, bbq, OWASP Top 10, CWE) and agent-level regression (38 test cases). Both must PASS for the agent task to execute.

External Systems

RHTPA / Trustify for vulnerability reports. GitLab / GitHub for issues and PRs. Maven Central for version verification. LLM providers (Gemini / OpenAI-compatible) for inference.

ADK Agent Service

Long-lived service on port 8080. Root coordinator delegates to 5 specialists. Plugins (SafetyPlugin + RedactionPlugin) wrap all agents. Resumable sessions via ADK ResumabilityConfig.

Task Types

select-cve

Pick the single best CVE to remediate. Routes to cve_selection specialist.

analyze-cves

Analyze all CVEs in the must-fix set. Routes to cve_analysis specialist.

remediate

Apply a dependency fix, verify build, open PR. Routes to remediation specialist.

generate-tests

Generate JUnit 5 tests, iterate until passing, open PR. Routes to test_generation specialist.

The agent service is stateless between requests but stateful within a session. ADK's ResumabilityConfig enables session resumption if the Tekton task needs to retry.
