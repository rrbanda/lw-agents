Trust & Safety

Five Layers of Protection

The system wraps agents in five independent safety layers. Each layer catches different failure modes. A failure at any layer blocks the operation.

Layer 1: SafetyPlugin

🛡 LLM-as-Judge Content Filter

A BasePlugin wired at the Runner level — wraps all agents and sub-agents. Uses a dedicated judge LLM to classify content as SAFE or UNSAFE.

Three hook points:

  • on_user_message_callback — screens incoming user messages
  • before_run_callback — blocks the run if user message was flagged
  • after_model_callback — screens model output before it’s returned

Blocks: jailbreak attempts, malicious code generation requests, data exfiltration attempts, infrastructure harm. Allows: legitimate security remediation, CVE analysis, dependency fixes.

Fails open on errors: if the judge LLM is unreachable, content is allowed through (logged as a warning). A crashed safety filter must not block legitimate work.

Layer 2: RedactionPlugin

🔒 Secret Masking on Tool Results

A BasePlugin with an after_tool_callback that applies regex-based secret masking to tool responses before they reach the model context. The LLM never sees raw credentials.

Shape-based patterns detected:

GitHub tokens (ghp_, gho_, ghu_, ghs_, ghr_) GitLab tokens (glpat-) API keys (sk-) Bearer tokens PEM private keys JWTs Basic auth Hex secrets (40+ chars)

Key-name masking: dictionary values with credential-related keys (token, secret, password, api_key, access_token, refresh_token, client_secret, etc.) are replaced with [REDACTED].

Layer 3: Pre-Gate

🚧 Input Validation Before Tokens

Validates remediation requests before the agent spends any LLM tokens. Implemented as before_agent_callback on the remediation planner.

Validation checks:

  • CVE ID matches CVE-YYYY-NNNN+ pattern (regex: ^CVE-\d{4}-\d{4,}$)
  • Package matches groupId:artifactId Maven coordinate format
  • Current and fixed versions both contain digits
  • Current ≠ fixed version (catches copy-paste errors)

Invalid requests receive a guidance-only Content response returned directly from the callback — the agent never runs, achieving zero model cost on bad input.

Layer 4: Post-Gate

🔍 Diff Validation After Execution

Validates the git diff after the agent runs. Implemented as after_agent_callback on the remediation planner.

Hard rejections — 7 forbidden patterns:

#nosec
Suppresses security linter
//noqa
Suppresses linter
@SuppressWarnings
Suppresses warnings
verify=False
Disables TLS verification
rejectUnauthorized:false
Disables TLS rejection
except: pass
Bare except-pass (swallows errors)
@PermitAll
Removes authentication

Hard limit: MAX_FILES_TOUCHED = 5 (rejection). Warning: MAX_DIFF_LINES = 100 (warning only, not rejection).

Layer 5: Fail-Closed Selection

🚫 Ambiguity Means No

The CVE selection callback in app/scoring/validate_selection.py. If any validation fails, the selection result is forced to SELECTED=0. The system fails closed.

Checked conditions:

  • Missing or invalid CVE ID
  • Invalid Maven coordinates (must match groupId:artifactId)
  • Versions without digits
  • Identical current and fixed versions
  • Empty justification
  • Placeholder values (string, null, none, n/a)

Every error path sets SELECTED=0 with empty fields and a validation failure message. There is no “maybe” state.

Defense in depth: Five independent layers means no single failure compromises the pipeline. A prompt injection that bypasses the SafetyPlugin still hits the pre-gate. A hallucinated fix that passes the pre-gate still hits the post-gate. The fail-closed selection ensures that even ambiguous agent output defaults to “no.”
