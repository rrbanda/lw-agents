Custom LLM-as-Judge Metrics

cve_selection_accuracy

Did the agent use lookup_cve_detail and check_version_exists before deciding? Is the selected CVE in the must-fix set?

version_not_hallucinated

Every version in the response was verified via check_version_exists before being reported. Unverified versions score 0.

correct_routing

Coordinator delegated to the correct specialist sub-agent. Wrong delegation, direct answers, or hallucinated agents score 0.

skill_loaded_first

Agent called load_skill via SkillToolset before making any substantive tool calls or decisions.

tool_use_completeness

All expected tools called with minimum counts. Partial credit (0.5) if most were called; 0 if critical tools missed.

remediation_build_passes

Build command executed and result was SUCCESS. Retries count — eventual success after retry still scores 1.

validation_gate_accuracy

All 4 gates (root_cause, instance_coverage, no_new_vulnerabilities, security_best_practices) match expected results. Scored 0–1 proportionally.

pr_hygiene

PR title mentions CVE ID, description explains changes, diff is minimal, no anti-patterns (nosec, SuppressWarnings, verify=false).

Automation Guarantees

⚡ Code Push Trigger

Every code push triggers the full pipeline via Tekton EventListener (agent-eval-listener). No manual intervention required.

🕓 CronJob Every 6 Hours

The scheduled-agent-eval CronJob (0 */6 * * *) runs evals even with no code changes — catches model drift and infrastructure shifts.

📊 Regression Detection

Each metric is compared against baseline.json with a 10% tolerance. Any regression beyond the threshold fails the pipeline.

🚫 Floor Enforcement

Absolute minimum thresholds per metric. Even if no regression, a metric below its floor blocks deployment. No exceptions.
