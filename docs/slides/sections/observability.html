Full-Stack Tracing with MLflow

Every LLM call, tool execution, and agent delegation is captured as an OpenTelemetry span and forwarded to MLflow on Red Hat OpenShift AI. Token counts, latencies, and full request/response payloads are recorded for every run.

What Gets Traced

👥 Agent Spans

Every agent run, delegation event, and state transition. ADK natively emits OTel spans for the full agent lifecycle.

⚙ Tool Spans

Every tool call with inputs, outputs, and duration. Custom tools can be wrapped with wrap_func_with_mlflow_trace() for additional coverage.

🤖 LLM Spans

Every inference request with model name, token counts (input + output), latency, and full response. Captured via mlflow.litellm.autolog().

Design Decisions

✅ Opt-In Activation

Tracing only activates when MLFLOW_TRACKING_URI is set. Without it, agents start normally with zero tracing overhead.

💚 Graceful Degradation

If MLflow is unreachable after a 5-second health probe, agents start normally without tracing. A warning is logged but nothing breaks.

📑 Two-Layer Capture

Layer 1: OTel TracerProvider captures ADK agent/tool spans. Layer 2: mlflow.litellm.autolog() captures LLM call spans with token counts.

🔌 Zero Agent Changes

Existing agents get full tracing without any code modifications. The TracerProvider is set globally before any ADK imports occur.

Configuration

Key environment variables controlling tracing behavior:

Variable Purpose Default
MLFLOW_TRACKING_URI Required to enable tracing. Points to the MLflow service. unset (tracing disabled)
MLFLOW_EXPERIMENT_NAME MLflow experiment for organizing runs. lw-agents
MLFLOW_WORKSPACE RHOAI workspace scope. Sent as X-MLflow-Workspace header. unset
MLFLOW_TRACKING_TOKEN Bearer token for RHOAI MLflow auth. unset
