Skills-First Architecture

Skills as Agent Playbooks

ADR-002 established a skills-first architecture. Agent behavior lives in SKILL.md files, not in Python instruction strings. The LLM loads the skill before acting — this ensures consistent methodology regardless of the model.

How Skills Work

Agent Starts
→
load_skill("cve-triage")
→
Full Methodology Loaded
→
Agent Follows Playbook
→
Structured Output

Seven Skills

cve-triage

CVE selection methodology. Explores must-fix CVEs one-by-one via tools, verifies fixed versions on Maven Central, and scores candidates by severity, release-line compatibility, and blast radius. Selects the single best CVE to remediate.

cve-analysis

Full must-fix set analysis. Iterates every CVE, evaluates fixability by verifying concrete fixed versions exist, classifies each as fixable or not, and outputs a JSON decisions array for the Tekton pipeline.

maven-remediation

Maven POM remediation procedure. Guides the agent through reading pom.xml structure, planning the edit (property overrides, BOM management, transitive dependencies), applying via OpenCode, build verification, and PR creation.

junit-test-generation

JUnit 5 test scaffolding and refinement. Analyzes project structure, identifies coverage gaps in service and business-logic classes, generates tests with Mockito, and iterates until mvn test passes.

scm-conventions

Git and SCM conventions shared across all agents. Defines branch naming patterns, commit message formats, selective git staging rules, PR body templates, issue body templates, and label standards.

validation-architect

Security architect review gates. Adversarial evaluation of fix design, data flow paths, and security controls against four weighted gates: root cause, instance coverage, no new vulnerabilities, and best practices.

validation-pentester

Penetration tester adversarial review. Attempts to bypass fixes using encoding variants, null bytes, type confusion, race conditions, error path bypasses, and default value divergence. Reports per gate from an attacker's perspective.

Why Skills, Not Instructions?

Instruction Strings

  • Embedded in Python code
  • Coupled to agent implementation
  • Hard to update without redeployment
  • Limited context window — all loaded at once
  • Not independently testable

SKILL.md Files

  • Separate markdown files in skills/
  • Version-controlled, independently updatable
  • Loaded on demand via load_skill
  • Progressive disclosure — full methodology with examples
  • Testable — evals verify the agent follows skill steps

Skills are the single most important design decision in this system. They encode expert methodology that the LLM follows step-by-step. When you want to change agent behavior, you edit a markdown file — not Python code.
